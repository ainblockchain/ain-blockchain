## 1. 지적사항 (심각도 순)

### R1 [지표 4 · 치명] 계획서 규정 측정법(Locust 240U/60W) 미준수
- **현상**: 합격 증빙 `m4-final-cert4.json` 은 자체 Node 클라이언트(`probe-inference.js`) **동시성 1,050** 으로 측정한 값(최대 1,199 TPS). 계획서가 규정한 "Locust 240 User / 60 Worker" 로 실측한 `cert_inference_240_stats.csv` 는 **98 TPS, 실패 33건** 이었고 증빙에서 제외돼 있었음. 절차서 §7.4 는 "측정법(240U/60W)은 계획서 규정이므로 변경 불가"라고 쓰면서 §7.5 는 Locust 의 10초 평균 `Requests/s` 를 최대 TPS 로 취함.
- **수정**: `locustfile.py` 전면 개정(기록 POST 를 사용자 태스크 밖 greenlet 으로 분리, 서버 목록 env 화, requestId 를 run 에 바인딩, **마스터가 Locust 자체 초당 성공 카운트(`num_reqs_per_sec`)를 덤프**) + `m4-run-locust.sh`(recorder ×2 → worker ×60 → master `-u 240 -r 240 --expect-workers 60` → drain → 검증) + `m4-verify-merkle.js` 가 **Locust 산출물만** 입력으로 받고 `users==240 ∧ workers==60` 을 pass 조건에 포함. `probe-inference.js` 는 "증빙 아님·사전 점검 전용" 으로 격하.

### R2 [전 지표 · 치명] 지표별로 다른 체인 설정 + 증빙 env 하드코딩(허위)
- **현상**: 지표 1~3 은 `cert-10-nodes`(epoch 1s, 대역폭 1e6), 지표 4~6 은 문서에 없는 수작업 설정 `cert-10-nodes-m4`(epoch **5s**, genesis 대역폭 5e4 → 온체인 수정 1e6) 위에서 측정. 지표 3 은 5s 체인에서 **불합격(평균 2,051ms)**. `common.js envSnapshot()` 이 `epochMs: 1000, validators: 10` 을 하드코딩해 `m4-final-cert4.json` 은 본문 "epoch 5s" 와 env "epochMs 1000" 이 모순.
- **수정**: 단일 설정 `cert-10-nodes` 로 통일하고 **전 지표를 같은 체인 인스턴스(genesis `0x3a5876f6…`)에서 재측정**. `envSnapshot()` 은 라이브 체인(`epoch_ms`·`bandwidth_budget_per_block`·검증자 수·genesis hash·SERVING 노드 수·마지막 블록)과 호스트(GPU 목록·코어·메모리)를 실측 조회. `start-cert-net.sh` 는 설정명을 인자로 받고 `cert-net.manifest.json`(설정·genesis·PID·시각)을 남김. `make-cert-config.js` 는 실제 사용 설정을 결정적으로 재생성(동일 genesis hash 확인).

### R3 [지표 3] "확정 블록 포함" 오표기 · 5개 GPU 노드 역할이 단일 프로세스
- **현상**: `VALUE_CHANGED(event_source: BLOCK)` 는 이벤트 노드가 **제안 블록을 실행한 시점**에 발생(확정 아님). 절차서 §1.2/§6.1 은 "확정 블록 포함"이라 서술 → 과장. 또 "5개 오프체인 GPU 노드" 를 한 프로세스의 5회 순차 제출로 구현.
- **수정**: `m3-latency.js` 를 관측 프로세스 1 + **GPU 노드 역할 워커 5(각각 다른 체인 노드 node1..5 로 제출)** 구조로 재작성. 판정값은 계획서 정의대로 **제출→블록 포함(inclusionMs)**, 참고값으로 **제출→확정(finalizedMs, 영수증 `FINALIZED` 관측)** 을 병기하고 정의를 결과 JSON 에 명시.

### R4 [지표 5·6] 정답 판정·온체인 역검증 부실
- **현상**: `hitOf` 가 단순 부분문자열 → `'352'` 가 `'35203'` 에, `'6018108008'` 이 `'60181080083'` 에 매칭(실제 진행파일에서 dart-007·009 오판). 온체인 역검증은 고정 sleep 후 제출 노드의 `getValue` → 풀에서 선실행된 값을 읽어 **블록 포함을 증명하지 못함**. publish anchor 가 현재 체인에 있는지 확인 안 함. quota 재시도 240회(2시간) 무제한.
- **수정**: 경계 일치 판정(정답 앞뒤가 영숫자가 아닐 것, 에러 본문은 불일치) + 단위 테스트. 모든 온체인 기록은 `common.recordAndVerifyFinal`(tx 영수증 `state==='FINALIZED'` → `getValue(is_final)` 일치) 로 통일. `/apps/knowledge/market/patches/<patch_id>` anchor 를 **현재 체인에서** `is_final` 로 확인해 pass 조건에 포함(`anchorsOnChain`). 다른 체인 인스턴스에서 공개된 수업은 재사용하지 않음. 재시도 40회 상한.

### R5 [지표 6 보조] `m6-record.js` 가 실제 lm_eval 결과에서 항상 실패
- **현상**: `n_samples`(실제 키 `n-samples`), 첫 하위 태스크를 그룹 대신 선택, `sample_len` 을 메트릭으로 취급 → 74개 결과 전부 `invalid metrics`.
- **수정**: `n-samples`/그룹 하위 합산/메트릭 키 필터(`name·alias·sample_len·sample_count·*_stderr` 제외), 정확도 계열 `[0,1]`·perplexity `>0`·나머지 유한성 검사. 74/74 결과 파일에서 유효 확인. 기록·역검증은 `recordAndVerifyFinal`.

### R6 [공통] `waitFinalized` 가 REVERTED 를 최종화로 집계
- **수정**: `state === 'FINALIZED'` 만 인정, `REVERTED`/미확정은 별도 상태로 기록. 지표 1·2·4 pass 조건에 그대로 반영.

### R7 [지표 4 검증] 검증기가 실행에 바인딩되지 않음 · 포함 증명이 허구
- **현상**: `M4_RUN` 기본값 불일치(recorder `run0` / verifier `cert4`), 배치 디렉토리 잔존물 전부 합산, 빈 디렉토리 크래시, "무작위 100건 멤버십"이 뽑은 배치 안에 그 레코드가 있는지만 검사(항상 참). recorder `/stats` 에 inflight 없음, `/flush` 즉시 반환 → 검증 레이스.
- **수정**: `M4_RUN` 필수, 배치 파일에 `run` 기록·검증, requestId 접두사(run)·중복·외부 id 검사, Locust 성공 건수의 ≥99% 기록 확인, **실제 머클 포함 증명(형제 해시 경로) 을 온체인 루트(is_final)에 대해 검증**(`m4-merkle.js` 공용화 + 단위 테스트), 앵커 tx `FINALIZED` 영수증. recorder 에 `/drain`(큐+inflight 0 까지 대기)·`inflight` 추가. 사장 코드(`m4-analyze.js`, `m4c-verify.js`)는 `legacy/` 로 이동.

### R8 [절차서] 실제 실행과 불일치
- **현상**: §3.2 `make-cert-config.js` 가 3-nodes 템플릿의 `min_stake_for_proposer 10,000,000` 을 두고 스테이크 100,000 → 검증자 목록이 비어 블록이 생성되지 않음, `cp -r` 로 옛 genesis gz 가 남아 생성기가 거부. §3.3 env(트래커 8080, PER_ACCOUNT 100000 등)·§7(GPU 5노드/14장/TP2/nginx, per-record recorder, `recorded_ids.json`)·§4/§5 스크립트 본문이 실제 하네스와 다름. 단일 호스트 리허설임이 명시되지 않음.
- **수정**: 절차서를 실제 하네스·스크립트·실측 환경 기준으로 개정(§2.4 실측 환경 매핑, §3.2 생성기 본문 교체, §3.3 실제 기동 스크립트, §4~§7 실제 스크립트·명령·판정 기준, §10 체크리스트).

### 지표 5·6 — Ainize 지식 패치 / DART 데이터셋 100종

새 노드(`home-cert`, 원장 = 위 체인)에서 108종 실행 중(트레이너 1개, 수업당 9~17분 실측). 완료 후 `--stack` 단계로 `m5-final.json`/`m6-final.json` 산출 예정. 이전 판의 12종 결과는 5s 체인 위였고 anchor 를 이전할 수 없어 폐기(`results/archive-5s-chain-20260910/`). 엄격 판정(경계 일치) 을 옛 12종 응답에 적용하면 11/12 가 통과하므로, 실패 수업은 새 이름(`__r2`)·effort balanced 로 1회 재학습한다.

### 실행 중 발생한 사고와 조치 (증빙 연속성)

- **체인 정지(블록 4204, 21:50)**: 검증자 10 프로세스를 코어 0-2 에 묶은 상태에서 지표 2 부하(앵커 80건 + CPU 워커 5)와 1,000블록 스냅샷 기록이 겹치자 epoch 이 밀려 같은 번호의 제안이 경합했고, 이후 모든 제안이 `mismatched state proof hash` 로 거부돼 정지했다. 조치: 정지 → 전 노드에서 잘린 스냅샷 `4000.json.gz` 를 `evidence/corrupt-snapshots/` 로 이동(블록 파일 4205개는 전부 정상) → `RESUME=1` 로 같은 데이터에서 재기동(genesis 동일 확인) → 검증자 코어 0-4 로 확대. 재기동 후 블록 4204 이전의 모든 온체인 증빙(지표 4 배치 루트, 지표 5 anchor)이 그대로 읽힘을 확인했다. 정지 중 진행하던 지표 5 수업 dart-003 의 anchor tx 는 유실돼 해당 수업은 `__r2` 로 재학습한다.
- 지표 1~3 결과는 이 재기동 **이후**의 4차 측정(`c4_*`)이며, 이전 회차(`m1-3-first-pass/`, `second-pass-before-final-fixes/`, `third-pass-no-cpu-affinity-field/`, `fourth-pass-before-reader-retry/`)는 하네스 수정 전 버전으로 참고용으로만 보존한다.
